## 0. Запуск сервера — БЛОКЕР

- [x] **Починить `npm run dev:server`** — сервер не поднимался.
  - **Причина (полная):** `apps/server/tsconfig.tsbuildinfo` (кэш инкрементальной компиляции TS, из-за `"incremental": true` в `apps/server/tsconfig.json`) был закоммичен в git. `nest-cli`'s watch-режим при каждом старте удаляет `dist/` (`deleteOutDir: true`), но НЕ трогает `tsconfig.tsbuildinfo` — TypeScript видит кэш, считает сборку актуальной и **не генерирует файлы заново**, из-за чего `nest start --watch` тут же падает на `Cannot find module '...dist/main'`. Это не разовая случайность: баг воспроизводится каждый раз, когда `tsconfig.tsbuildinfo` существует на диске перед запуском watch-режима — в том числе если его пересоздать локальным `npm run build`/`tsc` до `npm run dev:server`.
  - **Исправлено:** убрал `"incremental": true` из `apps/server/tsconfig.json` (сервер маленький, инкрементальность не даёт ощутимой выгоды, зато полностью убирает этот класс багов), убрал файл из git (`git rm --cached`), добавил `*.tsbuildinfo` в `.gitignore`.
  - **Проверено:** `npm run dev:server` поднимается стабильно, в том числе сразу после ручного `npm run build` (условие, которое раньше гарантированно ломало запуск).
  - Изменения пока не закоммичены — ждут отдельного коммита по твоей команде.

## Бот

- [x] **Бот-убийца** — сделано.
  - Логика в `packages/shared/src/bot/killer.ts`: чистые функции над состоянием, покрыты тестами. Сервер только отправляет их решения через обычный `applyCommand`, поэтому бот физически не может сходить против правил.
  - **Жертва:** перебор всех легальных целей с оценкой на ход вперёд — выбирается та, после которой у мотива остаётся больше будущих целей; при равенстве — подальше от машины.
  - **Испуг:** пугает тех, кого детектив реально может допросить (в квартале с машиной и по соседству), а своего персонажа и группу-помощника бережёт — через них можно лгать, а запуганный молчит.
  - **Ложь:** лжёт только если по этому признаку детектив ещё не получал ответа; иначе повторяет уже сказанное — два разных ответа на один вопрос выдали бы лжеца.
  - **Фаза Города:** уводит своих людей от машины, при пустом жетоне берёт самую многочисленную живую группу.
  - Сервер: слот бота в комнате (`isBot`), планировщик ходов с паузами (ночь 1.6 с, ответ 0.9 с) — ожидание читается как обдумывание. Бот ходит несколько раз подряд, когда нужно (ночь → фаза Города).
  - В меню режим «против бота»: партия стартует сразу, без лобби и кода.
  - Проверено вживую: бот убил двоих, запугал именно тех, кто стоял рядом с машиной, ответил на допрос и отыграл фазу Города.

- [x] **Усиление бота** (по просьбе после первой партии).
  - **Ложь «в образ».** Раньше бот отрицал свои признаки — на трёхзначных характеристиках это самораскрытие: «убийце 20?» — нет, «40?» — да, «60?» — да. Теперь бот выбирает живого жителя, максимально непохожего на себя («легенду»), и отвечает за него. По каждому признаку ровно одно «да», портрет непротиворечив и указывает на реального человека — детектив идёт по ложному следу, а не ловит бота на противоречии.
  - **Легенду бот не убивает** (штраф −1000 при выборе жертвы) и держит её, пока она жива, — алиби не должно исчезнуть.
  - **Выбор жертвы стал взвешенным:** `будущие цели × 8 + неоднозначность мотива × 6 + удалённость от убийцы × 4 + удалённость от машины`. Группу-помощника бережёт (−15).
  - **Неоднозначность мотива** — прямой ответ на новую панель мотивов: бот считает, сколько ещё кандидатов из шести разрешали бы это убийство, и выбирает жертву, которая не даёт детективу вычеркнуть ни одного мотива.

## Разворачивание для игры по сети

- [x] **Сервер раздаёт собранный клиент сам** (`app.useStaticAssets`). Один origin — нет ни CORS, ни второго адреса, ни отдельного хостинга для фронта. Роутер на hash-history, поэтому SPA-фоллбэк не нужен: все ссылки вида `/#/game/КОД`.
- [x] **Слушает 0.0.0.0**, а не localhost — иначе сервер не виден ни из локальной сети, ни из туннеля.
- [x] **Клиент сам определяет адрес сервера:** `VITE_SERVER_URL` → тот же origin (боевой режим) → `localhost:3000` (vite на 5173 и Electron с `file://`). Сборку не нужно пересобирать под каждый адрес.
- [x] **`ALLOWED_ORIGINS`** сужает CORS и у HTTP, и у сокета. Пусто — ведёт себя как раньше (`*`).
- [x] **`polling` в резерве** к websocket: часть прокси режет апгрейд.
- [x] `npm run serve` — собрать и поднять; `npm start` — поднять уже собранное.
- Проверено вживую на `http://localhost:3000`: меню, партия против бота, ночь, убийство, расселение — всё по одному адресу.

## Правила внутри игры

- [x] **Вкладка «Правила» в меню** — правый столбец теперь переключается между правилами и архивом сводок, правила открыты по умолчанию. Человек, который впервые открыл ссылку, попадает на объяснение игры, а не на список чужих партий.

## По итогам первой живой партии вдвоём

- [x] **Тупик в фазе Города (баг).** Если выпадал жетон группы, которой нет среди 20 жителей, партия вставала намертво — но только на ходу ДЕТЕКТИВА. Движок замену разрешал обеим сторонам, а кнопки выбора были сделаны лишь на экране убийцы; детектив видел сообщение «в группе никого не осталось» и не мог ничего нажать. Добавлен тот же выбор группы детективу. Регрессионный тест проверяет обе роли и то, что пустой жетон навсегда уходит из пула.
- [x] **Убийца видит все шесть версий детектива.** Раньше он знал только свой мотив и не понимал, среди чего его ищут — то есть не мог выбирать убийства, которые не вычёркивают мотивы. Странный перекос: бот это учитывал (`motiveAmbiguity`), живой игрок был слеп. Список кандидатов со своим помеченным — в папке убийцы.
- [x] **Жертвы: группа и испуг.** Смерть снимала испуг, поэтому факт «был запуган в момент убийства» просто исчезал из состояния. Добавлено поле `Victim.wasScared`, карточка жертвы получила цветную шапку по группе, подпись группы и отметку ЗАПУГАН/НЕ ЗАПУГАН. То же в списке жертв окна обвинения — это прямая улика против мотива «садист».
- [x] **Одного жителя нельзя допросить дважды за ход.** Раньше оба действия хода можно было потратить на одного человека. Теперь `turn.questionedCitizenIds` копит опрошенных за ход, обычный допрос их отклоняет, а закусочная под запрет не попадает и в список не пишет — она и остаётся способом вернуться к уже опрошенному. Со следующего хода запрет снимается. В интерфейсе строка жителя показывает «УЖЕ СПРОСИЛИ», действие гаснет с пояснением. Правило добавлено в справку (разделы «Детектив» и «Здания»), 2 теста.
- [x] **Ночь начинается с испуга.** Шаги в панели были пронумерованы «1 — запугать, 2 — жертва», а экран открывался на вкладке жертвы. Теперь порядок един: вкладки подписаны «1 · ИСПУГ» и «2 · ЖЕРТВА», по умолчанию активен испуг, после набора двух жителей экран сам переходит к выбору жертвы.
