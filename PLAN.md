## 0. Запуск сервера — БЛОКЕР

- [x] **Починить `npm run dev:server`** — сервер не поднимался.
  - **Причина (полная):** `apps/server/tsconfig.tsbuildinfo` (кэш инкрементальной компиляции TS, из-за `"incremental": true` в `apps/server/tsconfig.json`) был закоммичен в git. `nest-cli`'s watch-режим при каждом старте удаляет `dist/` (`deleteOutDir: true`), но НЕ трогает `tsconfig.tsbuildinfo` — TypeScript видит кэш, считает сборку актуальной и **не генерирует файлы заново**, из-за чего `nest start --watch` тут же падает на `Cannot find module '...dist/main'`. Это не разовая случайность: баг воспроизводится каждый раз, когда `tsconfig.tsbuildinfo` существует на диске перед запуском watch-режима — в том числе если его пересоздать локальным `npm run build`/`tsc` до `npm run dev:server`.
  - **Исправлено:** убрал `"incremental": true` из `apps/server/tsconfig.json` (сервер маленький, инкрементальность не даёт ощутимой выгоды, зато полностью убирает этот класс багов), убрал файл из git (`git rm --cached`), добавил `*.tsbuildinfo` в `.gitignore`.
  - **Проверено:** `npm run dev:server` поднимается стабильно, в том числе сразу после ручного `npm run build` (условие, которое раньше гарантированно ломало запуск).
  - Изменения пока не закоммичены — ждут отдельного коммита по твоей команде.

## Подтверждено как НЕ баг (закрыто без изменений)

- **4. Повтор действия одного типа через разные здания.** Физически за один ход не добраться до двух зданий одного типа (только 2 очка движения, здания разнесены по карте), а одно и то же конкретное здание дважды использовать уже нельзя (`usedBuildingIds`). Правок не требует.
- **5. Испуг жителя в квартале Детектива — разрешён.** Ошибка была в аудите: правило «нельзя» распространяется только на убийство, не на запугивание. `applyNight` менять не нужно.
- **7. 11 мотивов вместо 6 — верно.** Полный пул мотивов используется по замыслу, decoy-список из 11 корректен.

## 14. UI/UX — большая отдельная задача

- [ ] **Исправить конфликт Tailwind v3/v4.**
  - Диагноз: `apps/client` использует Tailwind v4 (`@tailwindcss/postcss`, CSS-based `@theme inline` в `src/index.css` с токенами в `oklch()`), но в репозитории также лежит старый `tailwind.config.js` в v3-стиле (`content`, `theme.extend.colors` на `hsl(var(--border))`, `keyframes`/`animation` для accordion, `plugins: [require("tailwindcss-animate")]`).
  - Этот JS-конфиг **не подключён** к v4-пайплайну (нет `@config` в CSS) — он полностью мёртвый. Из-за этого утилиты вроде `container` (центрирование/паддинг/брейкпоинты) и анимации `animate-accordion-down/up`, завязанные на shadcn-компоненты (Dialog/Select/Accordion), скорее всего не работают, а `tailwindcss-animate` дублируется (один раз мёртвым `require()`, один раз рабочим `@plugin` в CSS).
  - Фикс: удалить `tailwind.config.js` совсем (или явно перенести нужные куски — `container`, keyframes — в `@theme`/`@layer` внутри `index.css`), оставить единственным источником правды v4-CSS-конфиг.
- [ ] **Перенести новый дизайн поэтапно.**
  - Референс: [дизайн-концепт "Дело на столе"](https://claude.ai/code/artifact/9fa27a8e-07ba-424d-bfae-024fb9565c47?org=9c4bfe75-cc23-4ea6-9548-add9f92b715f) (Claude Design canvas).
  - Концепция: интерфейс = рабочий стол следователя 1940-х. Тёмная матовая столешница вокруг, светлая бумажная карта города — самый яркий и дорогой объект на экране (сейчас всё в игре одинаково тёмное — это и есть текущая проблема слабого UI/UX). Панели/кнопки/жетоны — материальные объекты (картон, латунь, печатная машинка), не плоские div-ы. Атмосфера через свет, а не через цвет; реализуемо на SVG+CSS без шейдеров/партиклов.
  - План переноса: согласовать по экранам (карта/доска, панель Детектива, панель Убийцы, карточка жителя, диалоги допроса/обвинения) и переносить по одному, не переписывая всё разом.
